================================================================
1. TUJUAN APLIKASI
================================================================

Aplikasi dipakai yayasan pendidikan untuk mengelola banyak
sekolah/madrasah dalam satu sistem.

Fokus utama:
- Admin Induk mengelola seluruh data yayasan dan seluruh sekolah.
- Admin Sekolah/Madrasah hanya mengelola sekolahnya sendiri.
- Guru/Pegawai hanya mengakses data pribadi dan fitur yang diizinkan.
- Data antar sekolah wajib terpisah.
- Hak akses tidak hanya berdasarkan menu, tetapi juga Policy dan query scope.
- Semua user tetap menggunakan satu sistem login.

================================================================
2. ROLE USER FINAL
================================================================

ROLE 1: admin-induk
-------------------
Fungsi:
- Dashboard seluruh yayasan.
- Mengelola semua sekolah/madrasah.
- Mengelola akun Admin Sekolah/Madrasah.
- Mengelola akun Guru/Pegawai.
- Melihat semua data Guru/Pegawai.
- Mengelola role/permission.
- Melihat laporan global.
- Mengakses pengaturan sistem.
- Mengakses audit log ketika modul sudah dibuat.

DATA SCOPE:
Semua sekolah/madrasah.

------------------------------------------------------------

ROLE 2: admin-sekolah
---------------------
Fungsi:
- Dashboard sekolah sendiri.
- Mengelola profil sekolah sendiri.
- Mengelola Guru/Pegawai sekolah sendiri.
- Membuat akun Guru/Pegawai untuk sekolah sendiri.
- Melihat laporan sekolah sendiri.
- Mengelola dokumen sekolah jika modul sudah tersedia.

TIDAK BOLEH:
- Melihat atau mengubah sekolah lain.
- Melihat Guru/Pegawai sekolah lain.
- Membuat akun Admin Induk.
- Mengubah role menjadi Admin Induk.
- Mengakses pengaturan global yayasan.

DATA SCOPE:
Hanya sekolah/madrasah yang ditugaskan.

------------------------------------------------------------

ROLE 3: guru-pegawai
--------------------
Fungsi:
- Dashboard pribadi.
- Melihat profil sendiri.
- Melihat data kepegawaian sendiri.
- Melihat informasi sekolah tempat bertugas.
- Mengubah data pribadi tertentu jika diizinkan.
- Mengunggah/melihat dokumen pribadi jika modul sudah tersedia.
- Melihat status pengajuan milik sendiri.

TIDAK BOLEH:
- Mengelola sekolah.
- Mengelola user global.
- Mengelola role.
- Melihat atau mengedit data pegawai lain.
- Mengakses pengaturan sistem.

DATA SCOPE:
Data diri sendiri + informasi sekolah yang memang diizinkan.

================================================================
3. JABATAN BUKAN ROLE
================================================================

Kepala Sekolah, Wakil Kepala Sekolah, Bendahara, Operator,
Guru, Tenaga Administrasi, dan jabatan lain TIDAK perlu dibuat
sebagai role login terpisah.

Mereka tetap berada pada role:
guru-pegawai

Jabatan disimpan di data pegawai, misalnya:

employee_type:
- guru
- pegawai

position:
- kepala-sekolah
- wakil-kepala-sekolah
- bendahara
- operator
- guru
- tenaga-administrasi
- lainnya

Dengan desain ini, sistem role tetap sederhana tetapi struktur jabatan
tetap fleksibel.

4. STRATEGI PANEL FILAMENT
================================================================

Gunakan SATU panel Filament terlebih dahulu:

/admin

Semua role login melalui panel yang sama.

Setelah login:
- admin-induk melihat menu global.
- admin-sekolah melihat menu sekolahnya.
- guru-pegawai melihat menu pribadi yang terbatas.

JANGAN membuat panel terpisah untuk setiap role pada tahap awal.

Keamanan wajib menggunakan:
- Spatie Role/Permission
- Laravel Policies
- Query/Data Scope

Catatan:
Menyembunyikan menu bukan keamanan utama.
User tetap harus ditolak jika mencoba membuka URL yang bukan haknya.

Relasi akun dengan sekolah.

Tujuan:
- Menentukan sekolah milik Admin Sekolah.
- Menentukan sekolah tempat Guru/Pegawai bertugas.
- Memungkinkan pengembangan lebih dari satu sekolah per user bila nanti dibutuhkan.

- school_id
- name

- nip nullable
- nik nullable

- birth_place nullable
- birth_date nullable
- employee_type
- position nullable
- employment_status nullable
- phone nullable
- email nullable
- address nullable
- is_active
- timestamps
- softDeletes

Catatan:
Akun login dan data pegawai DIPISAHKAN.
Tidak semua pegawai harus langsung memiliki akun login.

6. HUBUNGAN DATA
================================================================

SCHOOL
  |
  +---- EMPLOYEES
  |
  +---- SCHOOL_USER ---- USER
                         |
                         +---- ROLE

Contoh:

Admin Induk:
USER -> role admin-induk -> akses semua school

Admin Sekolah:
USER -> role admin-sekolah -> school_user -> Sekolah A

Guru/Pegawai:
USER -> role guru-pegawai -> school_user -> Sekolah A
                         -> employee -> data pribadi
